# 提交到 DSH 插件市场 · 操作步骤

> 这份是给你**自己动手**用的。**全程只用浏览器**（GitHub 网页 + npm 网站），见下面的「全网页版」。
> 结论文据：市场应用 `dshmarket` 的 README §"Submit your plugin"，
> 以及目录仓库 [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin) 的 `contributing.md`（17.6k 星）。

---

## 全网页版（不用命令行）· 先看这里

一件事必须说清楚：**npm 没有网页发布界面**，发布包只有命令行 `npm publish` 一条路
（官方社区"请求网页发布界面"的讨论至今开着）。
所以"纯网页"的做法是：**让 GitHub Actions 替你在云端执行 `npm publish`**，
你只在网页上点「Publish release」。仓库里已经放好了这个工作流：`.github/workflows/publish.yml`。

| 步骤 | 在哪做 | 说明 |
| --- | --- | --- |
| 1 | GitHub 网页 | 建仓库 + 用网页上传/新建文件 |
| 2 | npm 网站 | 注册账号 → 生成 Access Token（不发布，只拿 token） |
| 3 | GitHub 网页 | 把 token 存成本仓库的 Secret（`NPM_TOKEN`） |
| 4 | GitHub 网页 | Releases → Draft a new release → Publish（**自动发布到 npm**） |
| 5 | GitHub 网页 | Fork 目录仓库 → 新建一个 YAML → 提 PR |
| 6 | 本机（必须） | 装一次验证：这一步要 DSH 自己装，没有网页等价物 |

第 6 步必须在本机做（要在你机器上装插件、重启 DSH 看设置页）。其余全部网页完成。

---

## 第 1 步 · 在网页上建仓库并放文件

1. GitHub 右上角 **+ → New repository**
   - Repository name 填 `dsh-nutstore-backup`
   - 选 **Public**（市场只收公开仓库）
   - **不要**勾 "Add a README file" / .gitignore / license（我们本地已有这些文件，勾了会冲突）
   - 点 **Create repository**
2. 进入新仓库，点 **uploading an existing file**（首页那句 "…or upload an existing file"）
3. 把本目录下的文件**拖进去**。注意保留目录结构：
   - 必传：`package.json`、`cordis.patch.yml`、`README.md`、`LICENSE`、`.gitignore`
   - 必传：`lib/` 整个目录（11 个文件）
   - 建议传：`test/`、`docs/`、`.github/`（评审会看代码与测试，这是加分项）
   - **不要传**：`node_modules/`（本来也没有）
   - 提示：GitHub 网页上传支持拖拽文件夹，目录结构会保留
4. 底部 Commit message 填 `dsh-nutstore-backup: 坚果云备份插件`，点 **Commit changes**

> 如果网页上传对深层目录不友好，也可以先只传根文件，再用 **Add file → Create new file**，
> 文件名输入 `lib/index.mjs`（输入 `/` 会自动建目录），把内容粘进去。逐个文件重复即可。

5. 回到仓库首页，右侧 **About → ⚙️（齿轮）**，在 **Topics** 里加 `dsh-plugin`，保存。

> ⚠️ **仓库要满 1 天**才能提收录 PR（CI 自动检查，只是过滤"提 PR 前几分钟才建的仓库"）。
> 差一点就明天再提，重提没有任何负面影响。

---

## 第 2 步 · 在 npm 网站拿一个 Token（不发布）

1. 打开 https://www.npmjs.com/signup 注册（或用 GitHub 账号登录）
2. 邮箱验证完成后，右上角头像 → **Access Tokens**
3. **Generate New Token → Granular Access Token**
   - Name：`dsh-nutstore-backup-ci`
   - Expiration：按你习惯（例如 90 天）
   - Permissions：**Read and write**
   - Packages：选 **All packages**（首次发布时包还不存在，选具体的会选不到）
4. 生成后**立刻复制**（只显示一次）

> 只是拿个凭证交给 GitHub Actions 用，这一步不会发布任何东西。
> 顺便在 npm 网站确认 `dsh-nutstore-backup` 这个名字没被占用（https://www.npmjs.com/package/dsh-nutstore-backup
> 显示 404 就是可用；我已用 npm 接口查过，是空的）。

---

## 第 3 步 · 在 GitHub 网页上存这个 Token

1. 你的仓库 → **Settings** → 左栏 **Secrets and variables** → **Actions**
2. 点 **New repository secret**
3. Name 填 `NPM_TOKEN`（必须一模一样，工作流里就这个名字）
4. Secret 粘贴第 2 步复制的 token → **Add secret**

---

## 第 4 步 · 发 Release 即自动发布到 npm

1. 仓库 → 右栏 **Releases** → **Draft a new release**
2. **Choose a tag** → 输入 `v0.1.0` → 点 **Create new tag on publish**
3. Release title 随便填（如 `0.1.0`），描述可写这次改动
4. 点 **Publish release**

之后到 **Actions** 标签页能看到 `Publish to npm` 在跑。它会依次：

1. 校验 tag 与 `package.json` 的 `version` 一致（不一致就直接失败，避免"发了 Release 却没发布成功"）；
2. 跑发布前自检 `package-check`；
3. 跑 9 个测试套件；
4. 执行 `npm publish --access public`。

全绿之后，你的包就出现在 https://www.npmjs.com/package/dsh-nutstore-backup 。

> 以后每次发新版：先把 `package.json` 里的 `version` 改成新号（网页上点开文件 → 铅笔图标改 → Commit），
> 再按上面发一个对应 tag 的 Release（如 `v0.1.1`）。

---

## 第 5 步 · 提收录 PR（这一步就是"进市场"）

1. 打开 https://github.com/awesome-dsh-plugin/awesome-dsh-plugin ，右上角 **Fork** → **Create fork**
2. 在你的 fork 里：**Add file → Create new file**
3. 文件名填（注意是两个下划线，owner 换成你的 GitHub 用户名）：
   ```
   data/plugins/<你的用户名>__dsh-nutstore-backup.yml
   ```
4. 内容：

```yaml
url: https://github.com/<你的用户名>/dsh-nutstore-backup
name: <你的用户名>/dsh-nutstore-backup
category: session
description:
  en: 'Backs up DeepSeek Harness sessions, plugin config and workspace memory to Nutstore (Jianguoyun) over WebDAV, with incremental upload, connection test and one-click restore on a new machine.'
  zh: '把 DeepSeek Harness 的会话记录、插件配置与工作区记忆通过 WebDAV 增量备份到坚果云，支持连接测试与在新机器上一键恢复。'
```

5. 拉到底 **Commit changes**（可以直接提交到 main）
6. 回到 fork 首页，会出现 **Contribute → Open pull request**，点它 → 填个标题（如 `Add dsh-nutstore-backup`）→ **Create pull request**

**填的时候注意**（都是他们 `contributing.md` 里写明的）：

- `description.en` **必须以句号结尾**；
- 描述里含 `: `（冒号+空格）**必须加引号**——上面 `en` 用单引号包住就是为这条，否则 YAML 解析失败；
- **描述必须属实**，审稿人拿它逐条对代码。这句只说"增量上传 / 连接测试 / 一键恢复"，与实现一致，没有夸大；
- `category` 选贴合的：`session`（核心是会话与迁移）或 `dev` 都合理；选不准维护者会直接改，不会因此打回；
- 只加这**一个文件**，不要动两个 README（它们由脚本生成，手工改会冲突）。

---

## 第 6 步 · 装一次验证（这步必须在本机）

没有网页等价物，装上后要重启 DSH 看设置页：

```powershell
dsh plugin --profile web add dsh-nutstore-backup
```

若没有 `dsh` 命令（桌面版），就用手工方式，见 README §2.2。装完**重启 DSH**，
打开 **设置 → 坚果云备份**，确认页面出现、能登录、能备份。

这一步的结果值得写进 PR 描述（"已用 `dsh plugin add` 在 web profile 装过并跑通备份/恢复预览"）——
审稿人最认这种证据。

---

## 第 7 步 · 等 CI 与人工评审

- CI 校验形式：manifest、仓库年龄、YAML 格式、README 能否重新生成。**通过是前提，不是结论**；
- 维护者会真读仓库，核对描述是否名副其实；
- 合并后 CI 重新生成两个 README，站点与市场**通常一天内**出现你的条目。

## 先理解链路（1 分钟）

```
你的 GitHub 仓库  ──收录 PR──▶  awesome-dsh-plugin/data/plugins/<owner>__<repo>.yml
                                      │
                                      │ CI 每天生成
                                      ▼
                          awesome-dsh-plugin.com/plugins.json
                                      │
                                      │ 市场每次打开时实时拉取
                                      ▼
                     DSH 里的「插件市场」列表 → 用户点一下安装
                                      │
                                      ▼
                        dsh plugin --profile web add <你的包名>   （从 npm 取）
```

**两件事都要做**：① 发布到 **npm**（用户安装时从这里取包）；② 往 **awesome-dsh-plugin** 提一个 PR（让它在市场里被列出来）。
只发 npm 不会出现在市场；只提 PR 而 npm 上没有包，用户点安装会失败。

## 第 0 步 · 前置检查（先跑这个）

```powershell
cd "D:\My Agent\dev\dsh-nutstore-backup"
node test/package-check.mjs
```

必须是 **✅ 发布前自检通过**。它会检查市场/DSH 关心的那些硬性条件，其中两条是**最常见被打回的原因**：

- `dsh.bundle.patch` 必须存在（只声明 `dsh.client` 是**不能安装**的）——本项目已满足；
- 客户端半区必须是 `platform: "web"` + 传统脚本 `exports["./client"]`——已满足。

另外确认 `package.json` 里 `private` 必须是 `false` 或不存在（否则 `npm publish` 会被拒）。当前已是可发布状态。

---

## 第 1 步 · 建仓库并推上 GitHub

```powershell
cd "D:\My Agent\dev\dsh-nutstore-backup"

git init -b main
git add .
git commit -m "dsh-nutstore-backup: 坚果云备份插件（增量备份 + 换机恢复）"

# 在 GitHub 上新建一个空仓库（不要勾 README/.gitignore），然后把地址填到这里：
git remote add origin https://github.com/<你的用户名>/dsh-nutstore-backup.git
git push -u origin main
```

**当天不能提交**：目录仓库要求仓库**创建满 1 天**（CI 自动检查）。它只是过滤"提 PR 前几分钟才建的仓库"，不评价质量；差一点就第二天再提，重新提交没有负面影响。

推完之后在 GitHub 仓库页 **About 右侧齿轮 → Topics** 加上 `dsh-plugin`（这是明文要求之一）。

`node_modules/` 与 `*.log` 已经在 `.gitignore` 里，不会污染仓库。

---

## 第 2 步 · 发布到 npm

```powershell
# 1) 登录（会打开浏览器或让你贴 token）
npm login

# 2) 先看会发布哪些文件——应当是 13 个：lib/ 11 个 + cordis.patch.yml + README.md
npm pack --dry-run

# 3) 确认包名没被占用（返回 404 才是可用）
npm view dsh-nutstore-backup version

# 4) 发布
npm publish --access public
```

如果 `dsh-nutstore-backup` 这个名字已被别人占用，把 `package.json` 里的 `name` 改成一个带前缀的名字，例如 `@<你的用户名>/dsh-nutstore-backup`，然后：

```powershell
npm publish --access public     # scoped 包首次发布必须带 --access public
```

> 改了包名的话，后面 PR 的 YAML 里的 `name` 与用户安装命令都要跟着改。
> 包名一旦发布就**不能改**（只能发新包名），所以先 `npm view` 确认再发。

## 第 4 步 · 提收录 PR（这一步就是"提交到市场"）

1. 在 GitHub 上 **Fork** [`awesome-dsh-plugin/awesome-dsh-plugin`](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)；
2. 在你的 fork 里新建**一个文件**：`data/plugins/<你的用户名>__dsh-nutstore-backup.yml`
   （两个下划线分隔 owner 与 repo；**一个插件一个文件**，所以永远不会和别人冲突）；
3. 内容用下面这份（**只需要改 `url` 与 `name` 里的用户名**）：

```yaml
url: https://github.com/<你的用户名>/dsh-nutstore-backup
name: <你的用户名>/dsh-nutstore-backup
category: session
description:
  en: 'Backs up DeepSeek Harness sessions, plugin config and workspace memory to Nutstore (Jianguoyun) over WebDAV, with incremental upload, connection test and one-click restore on a new machine.'
  zh: '把 DeepSeek Harness 的会话记录、插件配置与工作区记忆通过 WebDAV 增量备份到坚果云，支持连接测试与在新机器上一键恢复。'
```

4. 提交 PR 到 `main`。

**填这个 YAML 时注意**（都是 `contributing.md` 里写明的坑）：

- `description.en` **必须以句号结尾**；
- 描述里含 `: `（冒号+空格）**必须加引号**——上面我给 `en` 加了单引号，就是为了这条；
- `zh` 可选，写不了中文维护者会补；你写中文没问题（全角冒号无影响）；
- **描述必须属实**——审稿人会拿它逐条对代码。上面那句只说了"增量上传 / 连接测试 / 一键恢复"，与代码一致，没有夸大；
- `category` 选**贴合实际功能**的。我选 `session`（核心是会话记录与迁移）；另一个合理选项是 `dev`。选不准维护者会直接改，不会因此打回。
